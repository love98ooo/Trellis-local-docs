Run `pnpm local:install` once in the fork source repository. The installer retains a fixed build and provides `~/.local/bin/trellis-local`; add `~/.local/bin` to PATH. Reuse this command in every worktree without reinstalling.

## Prerequisites

| Requirement | Minimum    | Why                                                                          |
| ----------- | ---------- | ---------------------------------------------------------------------------- |
| **Node.js** | 18         | `trellis` CLI runtime                                                        |
| **Python**  | 3.9        | Hooks and automation scripts (`python` on Windows, `python3` on macOS/Linux) |
| **git**     | any recent | Task branching, worktrees, and commit metadata                               |

`trellis-local init` checks the same Python command it will render into generated
files: `python --version` on Windows, `python3 --version` on macOS/Linux. If
that command is older than 3.9, init warns but does not block.

## Install Trellis

Run in the fork source repository:

```bash
pnpm local:install
```

Then initialize in your project:

```bash
trellis-local init
```

### Platform selection

By default, `trellis-local init` sets up for Claude Code. To include other platforms:

```bash
# Include Cursor support
trellis-local init --cursor

# Include multiple platforms
trellis-local init --cursor --pi

# All available platform flags
trellis-local init --claude       # Claude Code (default)
trellis-local init --cursor       # Cursor IDE
trellis-local init --opencode     # OpenCode
trellis-local init --codex        # Codex
trellis-local init --kiro         # Kiro
trellis-local init --gemini       # Gemini CLI
trellis-local init --qoder        # Qoder
trellis-local init --codebuddy    # CodeBuddy
trellis-local init --copilot      # GitHub Copilot
trellis-local init --droid        # Factory Droid
trellis-local init --pi           # Pi Agent
trellis-local init --kilo         # Kilo
trellis-local init --antigravity  # Antigravity
trellis-local init --devin        # Devin (formerly Windsurf)
```

### Other useful flags

```bash
trellis-local init -t electron-fullstack   # Use a spec template
trellis-local init --overwrite             # Overwrite existing specs when using template
trellis-local init --append                # Only add missing files from template
```

### What gets created

This creates a `.trellis/` directory with the default structure:

```
.trellis/
├── workflow.md          # How the workflow works
├── spec/                # Your coding conventions
│   ├── frontend/
│   ├── backend/
│   └── guides/
├── workspace/           # Session journals
└── tasks/               # Task tracking
```

For Claude Code, it also sets up `.claude/` with hooks, skills, agents, and session-boundary commands. For other platforms, it creates the corresponding config directory (`.cursor/`, `.opencode/`, `.codex/`, `.pi/`, `.agents/`, etc.).

## Updating Trellis

When a new version is released:

```bash
pnpm local:install  # in the fork source repository
cd /path/to/your-project
trellis-local update
```

Useful update flags:

```bash
trellis-local update --dry-run     # Preview changes without applying
trellis-local update --force       # Overwrite all managed files
trellis-local update --migrate     # Run file migrations (renames, deletes)
```

`trellis-local update` only touches unmodified files. Your customizations stay intact. A timestamped backup is created automatically before any changes.

## Uninstalling Trellis

To remove every file Trellis wrote into a project — `.trellis/` itself plus the platform-specific files under `.claude/`, `.cursor/`, `.codex/`, `.pi/`, etc. — run:

```bash
trellis-local uninstall              # interactive: lists what will be deleted/modified, asks Continue?
trellis-local uninstall --dry-run    # only print the plan, change nothing
trellis-local uninstall --yes        # skip the prompt (for scripts)
```

Trellis only removes files it tracks in `.trellis/.template-hashes.json`. Files you added under managed directories (e.g. your own hook scripts under `.claude/hooks/`) are never deleted. Structured config files such as `.claude/settings.json` keep your custom fields; only the trellis-owned hook entries are stripped.

## Add specs when needed

Open `.trellis/spec/backend/index.md` (or `frontend/` if that's your focus) and fill in the template.

Here's what a real spec looks like:

<CodeGroup>
```markdown Backend spec example
# Backend Guidelines

## Error Handling

All API endpoints return errors in this format:

{ "error": { "code": "VALIDATION_ERROR", "message": "Email is required" } }

Use AppError class from src/lib/errors.ts. Don't throw raw Error objects.

## Database

- Table names: snake_case, plural (user_sessions, not UserSession)
- Always include created_at and updated_at timestamps
- Foreign keys: {table}\_id format

```
</CodeGroup>

Be specific. Include file paths. Show actual code from your project. Vague guidelines don't help.

## Test it

Start a new Claude Code session and ask it to write some code. Check if it follows your specs.

If it doesn't, your specs probably aren't specific enough. Add more examples.
